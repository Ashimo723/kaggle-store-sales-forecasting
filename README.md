# Store Sales — Time Series Forecasting

[Kaggle: Store Sales - Time Series Forecasting](https://www.kaggle.com/competitions/store-sales-time-series-forecasting) の探索記録。
エクアドル Corporación Favorita の **54店舗 × 33商品ファミリ = 1,782系列**の日次売上を、16日先まで予測する（評価指標 RMSLE）。

**Public LB 0.41533 / 114位 · 647チーム（上位17.6%）** — 開始時 0.42567（142位）から −0.0103。

📊 **[探索レポートを見る](https://ashimo723.github.io/kaggle-store-sales-forecasting/)** — 48実験の全記録、検証設計、棄却された軸
（ソース: [REPORT.html](REPORT.html) — GitHub 上では生の HTML が表示されるため、上のリンクを推奨）

---

## 最終構成

5本の脚をブレンドする。**すべて同じ56特徴・同じ LightGBM** で、**学習データの切り方だけが違う**。
特徴量もハイパラメータも初期値から変えていない。

| 重み | 脚 | 学習単位 | 1分割の行数 |
|---|---|---|---|
| 0.40 | base | 全1,782系列を1モデル | 170万 |
| 0.20 | family別 | 商品ファミリごと（33分割） | 5.1万 |
| 0.20 | famgrp別 | 売上規模3分位 × ゼロ率（4群） | 28万 |
| 0.20 | gseas別 | 年次季節性3分位 × ゼロ率（5群） | 34万 |

```
特徴 56個 : 静的6 / カレンダー11（給与日を含む） / 祝日6（locale を店舗の city·state と突合）
            原油2 / onpromotion 4 / ラグ15（lag16〜364） / 移動集約12
目的変数  : log1p(sales) の L2 回帰（RMSLE と一致）
学習      : 2015-01-01 以降 / iter 900 / num_leaves 128 / lr 0.05 / seed 3本平均
ホライズン: 日付基準 lag >= 16 を厳守（test で入手不能な情報を使わない）
```

## 何が効いたか

特徴量・ハイパラ・目的変数・後処理はすべて飽和していた。唯一機能したのは
**同じモデルのまま学習データの切り方を変えて脚を作る**ことだった。

1. **単体性能で脚を評価してはいけない** — family別モデルは単体では base に負ける（27 fold 中7勝）が、
   30% 混ぜると **26/27 fold で改善**する
2. **商品側の切り口だけが有効** — store別（勝率0%）/ cluster別 / type別はすべて失敗。
   「同じ商品は店舗をまたいで似た挙動をするが、同じ店舗の異なる商品は似ていない」
3. **何を基準に集約するかで直交性が決まる** — 売上規模ベースの集約は互いに冗長だが、
   **季節性ベースだけが独立した情報**を持つ

### 直交性と単体性能のトレードオフ

| 脚の作り方 | 単体（base比） | 残差相関 | 結果 |
|---|---|---|---|
| 別アルゴリズム（Ridge / Croston） | +0.19 〜 +0.53 | 0.46 〜 0.76 | 単体が弱すぎて足せない |
| 別ライブラリ（XGBoost） | −0.0060 | 0.977 | 直交しないので効かない |
| **学習単位を変える** | +0.0148 | 中程度 | **両立する「谷間」** |

## 検証設計

最大の争点だった。最初の CV（2 fold）は **fold 間変動 0.069 に対し標準誤差 0.049** で、
検出したい効果 0.002 の25倍。**偶然で符号が決まる**状態であり、実際に2度、誤った施策を採用して LB を悪化させた。

**最終形（`src/cv3.py`）**
- 2016-06-01 から16日ステップで **27 fold**（重複なし、train = valid 開始日より前）
- **判定は必ず「同一 fold での対比較」** — fold 間変動を相殺する
- 27 fold 平均 0.4406 ≒ 実測 LB 0.42567（**絶対水準が一致**）

**採否基準（3度の改訂を経た最終形）— 3つすべてを満たすこと**
1. 勝率 ≥ 85%
2. 中央値 ≤ 平均差（利得が一様に分布し、少数 fold が平均を作っていない）
3. **最悪 fold の悪化 ≤ +0.002**

3番目は最後の失敗から得た。再帰予測は勝率93%・t=−4.50 を満たしたが、
**最悪 fold だけが +0.0074**（成功施策は +0.0010 以下）で、LB を +0.0063 悪化させた。

## リポジトリ構成

```
submit.py         最終構成で提出ファイルを作る（これ1本で完結）
src/
  common.py       RMSLE / fold 生成 / 提出書き出し（行数・id順序・NaN・負値を検算）
  features.py     56特徴の生成（ホライズン整合 lag>=16 を担保）
  cv3.py          27 fold rolling origin CV（最終的な検証設計）
  cv2.py          初期の 2 fold CV（分散不足で降格。経緯の記録として残置）
  e01〜e48        各実験のスクリプト（1実験 = 1ファイル、番号は EXP_LOG と対応）
  recursive.py    再帰予測（棄却したが実装は残置）
  legs.py         異質な脚（Ridge / Croston / 同曜日平均 / 前年同期）
experiments/
  EXP_LOG.md      全48実験の時系列ログ（仮説・変更・結果・判定）
  KEEPERS.md      現在の best の構成と、各要素を残している理由
  GRAVEYARD.md    棄却した18件と、それぞれの再挑戦条件
  IDEAS.md        未実装の仮説
REPORT.html       探索レポート
```

## 再現方法

```bash
pip install numpy pandas scikit-learn lightgbm pyarrow

kaggle competitions download -c store-sales-time-series-forecasting -p data
unzip -o 'data/*.zip' -d data

python3 submit.py --smoke   # 動作確認（seed 1本 / iter 100、約1.5分）
python3 submit.py           # 本番（約35分）→ output/submission.csv
```

`submit.py` はデータ読み込みから特徴生成・4脚の学習・ブレンド・提出ファイルの検算まで
**1本で完結する**。出力される CSV がそのまま LB 0.41533 の構成にあたる。

```
[1/3] 特徴量を生成（初回は約1分、2回目以降は output/panel.parquet を再利用）
      学習 1,703,592 行 / 予測 28,512 行 / 特徴 56 個
[2/3] 4本の脚を学習（seed 3本 x iter 900）
      base → family(33) → famgrp(4) → gseas(5)
[3/3] ブレンドして書き出す
      base    平均   440.11  相関(base) 1.0000
      family  平均   442.27  相関(base) 0.9979
      ...
```

各実験を個別に再現する場合は `python3 src/e<NN>_*.py`。実験間の依存は
`output/e39_pred_*.npz` などの予測キャッシュを介しており、
ブレンド比率の再探索（`e41`, `e43`）は再学習なしで走る。

## 検証せずに真似しなかったもの

公開されている LB 0.37984 のノートブックから3つの手法を抽出して検証したが、
**いずれも我々の構成では悪化した**。

| 手法 | 結果 |
|---|---|
| 祝日を種類別ダミーに展開 | t=−1.52。各祝日が年3〜5サンプルしかなく gain 0.00004 |
| ゼロ売上日の線形補間 | **+0.3460 で壊滅**。休業は予測可能なパターンで、消すと予測能力を失う |
| 再帰予測（1日先モデル×16回） | CV −0.0029（勝率92%）→ **LB +0.0063 の逆転** |
